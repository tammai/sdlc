# Spec 11: Claude Code, Codex, Cursor and Antigravity

The plugin installs and runs on its own in Claude Code, Codex, Cursor and Antigravity. Setup knows which agent is running it and writes that agent's files without asking. When a second agent opens a repo another agent already set up, its setup adds only its own layer and carries over what the first team wrote. [Issue #1](https://github.com/tammai/sdlc/issues/1); the design is in [ADR 0007](../adr/0007-multi-tool-adapters.md).

**Entry points:** `/sdlc:setup` (or the `setting-up-projects` skill), `/sdlc:upgrade`, `/sdlc:eject`, `/sdlc:doctor` · **Source:** `scripts/scaffold.py host`, `add-host` and `agents`, `scripts/hosts.py`, `hosts/hook.py`, `templates/project/agents/workflow.md`, `templates/project/ci/invariants.py`, the Codex, Cursor and Antigravity manifests, `hosts/`

## Install

| Agent | Install | Reads |
|---|---|---|
| Claude Code | `/plugin marketplace add tammai/sdlc`, then `/plugin install sdlc@sdlc` | `.claude-plugin/` |
| Codex | `codex plugin marketplace add tammai/sdlc`, then `codex plugin add sdlc@sdlc` | `.agents/plugins/marketplace.json`, then `.codex-plugin/plugin.json`: skills from `skills/` and `hosts/skills/` |
| Cursor | Customize → Import from Repo, or put a clone in `~/.cursor/plugins/local` | `.cursor-plugin/`; agents from `hosts/cursor/agents/` |
| Antigravity | `python3 scripts/hosts.py dist antigravity <folder>` in a clone, then `agy plugin install <folder>` (a direct `agy plugin install https://github.com/tammai/sdlc` loads only 3 of the 13 agents) | root `plugin.json`, `skills/`, `hosts/skills/`, `agents/` |

## User scenarios

1. **Setup in Codex.** Given the plugin is installed in Codex, when the user asks to set up sdlc in a new repo, then setup records `hosts: ["codex"]` without asking which agent this is. The shared setup runs, and `AGENTS.md` gets the sdlc block with the workflow and the policy rules. Nothing is written under `.claude/`.
2. **Claude Code joins.** Given that repo, when a Claude Code user runs `/sdlc:setup`, then setup sees it's joining, so it runs only the Claude Code layer (rules, guardrails, allowlist) and `scaffold.py agents`. The team's own `AGENTS.md` text reaches Claude Code through `.claude/rules/sdlc-agents-md.md`. The commands, baseline and constitution are not redone.
3. **Codex joins a Claude Code repo.** Given a repo Claude Code set up, when a Codex user runs setup, then `AGENTS.md` gains the block, built from `CLAUDE.md`, the team's `.claude/rules/` and the plugin's policy rules. The team's own text outside the block is untouched.
4. **Can't tell.** Given Codex was started from a Claude Code shell and the plugin was loaded from a checkout, when setup runs, then it asks which agent this is: the only question it asks about hosts.
5. **Drift.** Given a teammate edits `CLAUDE.md`, when anyone runs `/sdlc:doctor`, then the `AGENTS.md` check warns and names `scaffold.py agents`.

## Guarantees per agent

Every `[enforced]` requirement in specs 02–06 rests on one of these mechanisms, and the mechanism decides what each agent gets.

| Mechanism | Examples | Claude Code | Codex | Cursor | Antigravity |
|---|---|---|---|---|---|
| Plugin hook: freshness, trust anchor, hookify guardrails | Stale results in Prove (Stage 5), changed anchors, team guardrails | enforced | enforced once the hooks are trusted (`/hooks`); guardrails only where Claude Code set them up | enforced; guardrails only where Claude Code set them up | enforced in the CLI (`dist` install); guardrails only where Claude Code set them up |
| Plugin hook: role guard, model router, prove budget, security hooks | reviewers can't edit, dispatches name a model, Prove's 120 s command cap, security review | enforced | instructed | instructed | instructed |
| Plugin script run by a skill | scaffold, doctor, `diff_stats.py` | enforced | enforced, if the agent finds the plugin folder | same | same |
| Subagent roles | fresh verifier, read-only reviewers | enforced (tools per agent) | instructed: Codex agents can't be made read-only, and plugin agents aren't loaded | reviewers `readonly`; the verifier instructed | instructed: all 13 load from the `dist` copy; no read-only flag |
| Generated CI (`sdlc-verify`) | the full test suite on the merged code | enforced | enforced | enforced | enforced |
| Generated CI (`sdlc-invariants`) | test-report rounds, baseline growth, `[inferred]` tags | enforced | enforced | enforced | enforced |
| Policy rules | code style, tests, migrations, sensitive areas, CI, UI | `.claude/rules/`, glob-scoped | `AGENTS.md` block, always loaded | same | same |

## Known gaps

- **Smoke test so far (2026-10-24).** Codex, Antigravity and Cursor install from the checkout on Windows and in WSL. Scenario 1 ran to the end in Codex (Windows, PowerShell), Antigravity (Windows) and Cursor (WSL): each recorded only its own host, and gave the block in `AGENTS.md` and a clean doctor. Codex and Antigravity then passed it in WSL too. Claude Code ran scenario 2 in the Codex repo. One WSL Codex run made a single setup commit and skipped the `.gitignore` step. The skill asks for both, but nothing outside Claude Code enforces them; doctor flagged the missing entry.
- **Codex turns only some commands into skills by itself**, and none that take `$ARGUMENTS`. Antigravity reports "converted to skills" but loads none. Hence `hosts/skills/` (AGT-FR-012). Cursor reads `commands/` through its manifest, but whether `/sdlc:start` loads there is unconfirmed.
- **Codex on Windows runs commands in PowerShell.** The skills are written for bash (`S="python3 …"`, `$S status`, heredocs). In the smoke test, Codex rewrote them in PowerShell by itself, and nothing failed on syntax. That is model behaviour, not something the plugin guarantees.
- **Finding the plugin folder outside Claude Code** relies on the agent knowing where the file it loaded lives. Codex showed that it knows its `SKILL.md` path; Cursor and Antigravity are unverified.
- **Antigravity needs the `dist` copy.** It reads `agents/` itself and skips any agent with a model tier (`opus`, `sonnet`, `haiku`) or comma-string `tools`. Its `plugin.json` can't point elsewhere, and an install copies only the folder it's given. A direct install from the repo URL loads 3 agents. `agy plugin import` copies the agents unchanged, and imports the Claude Code hooks too, so don't use it.
- **Hooks outside Claude Code.** Smoke-tested on 2026-10-25 in Codex 0.162 on Windows and in WSL, in cursor-agent 2026.10.22 in WSL, and in Antigravity CLI 1.4.7 on Windows. In each, a stale Stage 5 Stop kept the agent going until it reran the tests, and a hookify rule denied `rm -rf`. In Cursor, the Stop caught an edit made with `sed`.
  - **Trust.** Codex runs plugin hooks only after the user trusts them in `/hooks`, and again after every plugin update.
  - **Guardrails need Claude Code.** The hookify rules sit in `.claude/hookify/`, which setup writes only on Claude Code. A Codex-only repo has none.
  - **Test results.** A full test run in Codex records `last_result: unknown`, because Codex sends a command's output without its exit code. Antigravity sends neither, so the same holds there. Cursor sends it.
  - **Cursor headless.** `cursor-agent -p` fires no `stop` or `beforeSubmitPrompt`, so the Stop checks run only in interactive sessions. Cursor on Windows (PowerShell) is untested.
  - **Antigravity** runs hooks in the CLI only; the `dist` install is the supported one. It has no hook that can stop a prompt, so a hookify prompt block reaches the agent as a message instead. A warning on a tool call becomes the `reason` of an `ask`; whether Antigravity shows it in its approval prompt is unconfirmed. The hook command tries `python3`, then `python`; if neither runs, Antigravity fails closed and denies every command and edit. Antigravity on WSL and Linux is untested.
  - **Left out for now:** the role guard, the model router, the prove budget, the security review and the Ralph loop.
- **No glob scoping outside Claude Code.** Policy rules sit in `AGENTS.md`, so they always load. Writing `.cursor/rules/*.mdc` or `.agents/rules/*.md` would duplicate them, because those agents read `AGENTS.md` too.
- **Codex's 32 KiB cap** on the combined `AGENTS.md` text: the block is about 10 KB with every policy rule. `agents` and doctor warn when the root file passes the cap (AGT-FR-018); nested `AGENTS.md` files in subfolders aren't counted.
- **`AGENTS.override.md`** at the root makes Codex skip `AGENTS.md`, and with it the block.
- **Enabling the plugin for the team** exists only for Claude Code (`.claude/settings.json`). Other agents' users install it themselves.
- **Shared files outside Claude Code.** `sdlc-invariants` (AGT-FR-019–023) checks test reports, the baseline and `[inferred]` tags in CI. It catches a bad change at the pull request, not when it's made: setup installs no pre-commit hook, and a team that wants one adds `python3 .sdlc/ci/invariants.py --base HEAD` to its hook manager. Public Surface declarations aren't checked: `diff_stats.py` lives in the plugin, not the project. Ownership (AGT-FR-024) is instructed: nothing stops an agent that ignores it, and a repo with its own CI gets the check from setup only when it accepts it.
