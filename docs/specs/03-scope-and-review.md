# Spec 03: Scope tracing and review

Every addition is traced to a request from intent to diff, and review gets measured facts so unrequested scope is caught mechanically where possible.

**Entry points:** Define and Review; `/sdlc:review-pr`, `/sdlc:code-review` · **Source:** `skills/orchestrator/references/flow.md` (Define, Review), `s-track.md`, `review-brief.md`, `templates/change-template.md`, the state template in `references/flow.md`, `templates/plan-template.md` (a part's plan), `agents/code-reviewer.md`, `commands/review-pr.md`, `plugins/sdlc-extras/agents/` (comment-analyzer, type-design-analyzer, code-simplifier), `scripts/diff_stats.py` · **Decision:** [ADR 0003](../adr/0003-guard-against-over-engineering.md), [ADR 0020](../adr/0020-sdlc-2-slim-process-core.md)

## User scenarios

1. **A proposal nobody asked for.** Given Define would add "audit logging" the user never asked for, when it writes the change file, then it lists it under the proposals not asked for, with a reason, and drops it unless the user keeps it.
2. **Undeclared export.** Given a state file whose Public Surface lists `createSession`, when the diff also exports `sneaky`, then `diff_stats.py --plan` flags it as undeclared, which reviewers treat as high severity.
3. **Review picked from the diff.** Given a change that touches a migration path, when the build ends, then the agent recommends a security review with that reason.

## Non-goals

- Blocking merges automatically on diff facts: they're evidence for reviewers, not verdicts.
- Detecting endpoints, CLI commands, config keys or env vars mechanically.

## Known gaps

- A medium or low bug the closing check (round 2) lists is fixed test first by instruction only: its report passes, and no gate checks that each listed bug got its test and fix (`verify.py` doesn't know the finding ids).
- Tracing through the change file and the plan is instructions plus, on M and L, the user's approval; on S nobody reads them before the build.
- Which reviews run is a recommendation; on S a recommendation of none means no reviewer checks the surface flags.
- Reviewers can't edit files: the code-reviewer has Write only for its report under `.sdlc/.work/findings/`, and the role-guard hook denies every other file edit to every `sdlc:` and `sdlc-extras:` reviewer, `ui-reviewer` included (any file under `.sdlc/.work/findings/` is allowed, so a misnamed report there isn't caught). They keep Bash (for `git diff`, tests and browsers), so a shell edit is still only instructed against; the freshness hook's worktree diff catches one during Review (Stage 3).
- The round cap's store (`.sdlc/.work/review-rounds.json`: rounds seen, the last round the user's grants allow, the ceiling) is a file the agent could write with a shell command; the hook trusts it as it did the grants before. And where the host never sends the user's prompt to hooks (headless Cursor), a raise only reaches features started after it is committed; and the typed command is matched as `/` or `$`, then `setup`, `sdlc:setup` or `sdlc-setup`, then `review-rounds` and one to three digits, in any case; a nested session the agent starts (`claude -p "/sdlc:setup review-rounds 5"`) is a user prompt to the hook; and a raise the agent commits during one feature becomes the next feature's Base value, seen only in that PR's diff.
- Export detection is regex-based for TS/JS, Python and Go; other languages get comment counts only.
