# Spec 02: Orchestration

The orchestrator takes a request through the lifecycle in four phases (Define, Build, Prove, Ship with Learn): sizes it, runs each phase with the bundled pieces, records progress in `.sdlc/state/<feature>.md`, and stops only at hard stops.

**Entry points:** `/sdlc:start [request]`, `/sdlc:status`, `/sdlc:deploy` · **Source:** `skills/orchestrator/SKILL.md` (the core) and `skills/orchestrator/references/` (`start.md`; one file per phase: `define.md`, `build.md`, `prove.md`, `ship.md`; `backlog-slices.md`, `review-brief.md`, `ui-work.md`; `operate.md`, reference only), `scripts/state.py` ([spec 12](12-control-contract.md)), `commands/start.md`, `commands/deploy.md`, `scripts/backlog.py`, `scripts/autopilot.py`, `templates/backlog-template.md`, `hooks/model_router.py`, `hooks/role_guard.py`, `hooks/trust_anchor.py`, `templates/spec-template.md` and `templates/plan-template.md` (AC ids, `## Acceptance tests`, the Deviations line)

## User scenarios

1. **Start a feature.** Given a set-up repo with no active feature, when the user runs `/sdlc:start add CSV export`, then the orchestrator proposes a track with its reason, creates `state.md` at `Current: Stage 1 – Define`, announces track, risk, flow and `Build:`, and starts Define.
2. **Resume.** Given one `state.md` with `Status: active`, when the user runs `/sdlc:start` with no argument, then it summarizes feature, phase and open items in 2–3 lines and continues in that phase's file. Given several, it asks which.
3. **Repo not set up.** Given no `.sdlc/config.json`, when the user starts work, then it stops and offers setup; if declined, it continues with detected commands and records a Deviation.
4. **Skip a gate.** Given a gate in progress, when the user says "skip" or "just ship it", then it names the gates being skipped, records them under Deviations, and complies.

## Requirements

Citations: "orchestrator: core" is `SKILL.md`; "orchestrator: start", "define", "build", "prove" and "ship" are those files in `skills/orchestrator/references/`; "Backlog slices" is `backlog-slices.md`. Each phase runs at one internal stage number, which `state.py` writes and the hooks read: **Define = Stage 1, Build = Stage 4, Prove = Stage 5, Ship = Stage 8**. A requirement that names a stage number means that phase; 2, 3, 6, 7 and 9–11 occur only in features started under the old 11 stages.

## Edge cases

- Several active features → ask which (doctor warns: test_doctor › test_feature_state).
- A paused feature (`Status:` other than `active`) is not picked up by `/sdlc:start`.
- The S track has no design file and no approval: Define writes short `intent.md`, `spec.md` and `plan.md`.

## Non-goals

- Running phases in parallel (Prove's checkers do run in parallel, on one commit); managing several features in one turn.
- Choosing the track without the user being able to override.
- Mirroring phases or tasks into Claude Code's native task list. `state.md` is the tracker; the task tools are off by default on current models (Claude Code ≥ 2.1.268) and can't be read by hooks or doctor.

## Known gaps

- The trust anchor makes changes visible, it doesn't prevent them: its own state (`.sdlc/.work/trust-anchor.json`), the freshness state and the dispatch log are files the main session can write (the role guard keeps the plugin's subagents off them). A damaged record is a notice, but a deleted one looks like a first run, and editing the hooks isn't detected.
- Apart from the model router (ORC-FR-015), every orchestration rule is `[instructed]`: nothing mechanically prevents skipping a phase or a hard stop. The user's approval at hard stops is the control.
