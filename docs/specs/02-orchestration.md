# Spec 02: Orchestration

The orchestrator takes a request through the lifecycle in four phases (Define, Build, Review, Ship with Learn): sizes it, runs each phase with the bundled pieces, records progress in `.sdlc/state/<feature>.md`, leaves the same record at every size, and stops only at hard stops. sdlc 2.0 ([ADR 0020](../adr/0020-sdlc-2-slim-process-core.md)).

**Entry points:** `/sdlc:start [request]`, `/sdlc:status`, `/sdlc:deploy` · **Source:** `skills/orchestrator/SKILL.md` (the core) and `skills/orchestrator/references/` (`flow.md`, all of M and L; `s-track.md`, all of S; `backlog-slices.md`, `review-brief.md`, `ui-work.md`; `operate.md`, reference only), `scripts/state.py` ([spec 12](12-control-contract.md)), `commands/start.md`, `commands/deploy.md`, `scripts/backlog.py`, `scripts/autopilot.py`, `templates/backlog-template.md`, `hooks/model_router.py`, `hooks/role_guard.py`, `hooks/trust_anchor.py`, `templates/change-template.md` (why, decisions, AC ids, `## Acceptance tests`, `## Review`), the state template in `references/start.md` (how the build runs, handoff, tasks, Public Surface, Deviations) and `templates/plan-template.md` (a part's `plan-B<n>.md`)

## User scenarios

1. **Start a feature.** Given a set-up repo with no active feature, when the user runs `/sdlc:start add CSV export`, then the orchestrator proposes a track with its reason, creates `state.md` with `Process: 2` at `Current: Stage 1 – Define`, announces track and risk, and starts Define.
2. **Resume.** Given one `state.md` with `Status: active` and `Process: 2`, when the user runs `/sdlc:start` with no argument, then it summarizes feature, phase and open items in 2–3 lines and continues in that phase's file. Given several, it asks which.
3. **A 1.x feature.** Given an active `state.md` without `Process: 2`, when the user runs `/sdlc:start`, then it says the feature was started under sdlc 1.x and must be finished with sdlc 1.8.1 or archived (`Status: done`).
4. **Repo not set up.** Given no `.sdlc/config.json`, when the user starts work, then it stops and offers setup; if declined, it continues with detected commands and records a Deviation.
5. **Skip a step.** When the user says "skip" or "just ship it", then it names the steps being skipped, records them under Deviations, and complies.

## Edge cases

- Several active features → ask which (doctor warns: test_doctor › test_feature_state).
- A paused feature (`Status:` other than `active`) is not picked up by `/sdlc:start`.
- A 1.x feature in progress at upgrade: `/sdlc:upgrade` refuses until it is finished on 1.8.1 or archived (SET-FR-045).

## Non-goals

- Running phases in parallel (the chosen reviews do run in parallel, on one commit); managing several features in one turn.
- Shipping parts of a change separately: all parts land together.
- Choosing the track without the user being able to override.
- Mirroring phases or tasks into Claude Code's native task list. `state.md` is the tracker; the task tools are off by default on current models (Claude Code ≥ 2.1.268) and can't be read by hooks or doctor.

## Known gaps

- The trust anchor makes changes visible, it doesn't prevent them: its own state (`.sdlc/.work/trust-anchor.json`), the freshness state and the dispatch log are files the main session can write (the role guard keeps the plugin's subagents off them). A damaged record is a notice, but a deleted one looks like a first run, and editing the hooks isn't detected.
- Which reviews run is the agent's judgment (the user's on M and L). On S a recommendation of none means no agent reads the tests against the criteria, so a test that runs and passes but asserts the wrong thing is caught only by its red record.
- Whether the agent asked enough before building is its own judgment; nothing checks that a question it should have asked was asked.
- Push, PR and the single CI fix are instructed; nothing checks that Ship stopped at the PR rather than merging.
- Apart from the model router (ORC-FR-015), the trust anchor (ORC-FR-018) and `state.py`'s refusal of a 1.x feature (ORC-FR-039), every orchestration rule is `[instructed]`: nothing mechanically prevents skipping a phase or a hard stop. The user's approval at hard stops is the control.
