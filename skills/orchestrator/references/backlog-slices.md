# Backlog slices

For a feature too big for one session, so the work can pause, `/clear` and resume between slices, or run in fresh sessions (autopilot). S never gets a backlog; a feature that fits one session keeps the plain phase loop. Each slice runs Build (`build.md`, ending in a passing `verify.py`), then commits; there is no Prove per slice. Prove runs once, at Feature close, on every backlog, unless `Prove: skip` (then the last slice goes to Ship). Ship and Learn wait for Feature close.

1. **Backlog.** Write `<intents>/backlog.md` from `${CLAUDE_PLUGIN_ROOT}/templates/backlog-template.md`: one row per vertical slice (something a test or user can see working end to end), with its FRs, acceptance criteria, dependencies and size. Every spec FR is in some row. It is approved with the spec and `plan.md` (whose per-slice how-outline it follows) in Define's one approval, on any track. `state.py set <f> Flow lite` in the same turn as that approval message, so the user's approval also accepts the trust anchor's `Flow:` notice.
2. **Flow.** `Flow: lite` at any track and risk; tiers per the core's table. L keeps its design in Define and its Learn extras. `Base:` stays the feature's start; full security, Learn and Ship run once, at Feature close.
3. **Pick the slice:** `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/backlog.py" next <intents>/backlog.md` (a slice in progress, else the first `todo` whose dependencies are done; `check <backlog> B<n>` for a named one, refused while its dependencies aren't done). Nothing ready while rows remain (a `blocked:` row, or open dependencies) → say which and stop; every row `done` → Feature close. Then `state.py slice <f> start B<n>` (sets `Slice:` and `Slice base:` and the row to `in progress`) and `state.py advance <f> 4` (`--gate pass` from Define; from Stage 6 after the previous slice's commit).
4. **Each slice** (phase headers as usual):
   - Build: first `<intents>/plan-B<n>.md`, from `${CLAUDE_PLUGIN_ROOT}/templates/plan-template.md` and the slice's outline in `plan.md`: 3–6 tasks, each naming its files, first test, command and FR, plus `## Public Surface`. No planning skill. Then build from it as `build.md` says (deviations go in `plan-B<n>.md`).
   - Commit, once `verify.py` passes on the slice, at Stage 6 (the slice's resting point, never 8: autopilot and the trust anchor read Stage 8 as "feature close reached Ship"): `state.py verified …` (the `tree` from `verify.py status`) and `advance <f> 6 --gate pass`, then only the core's verified-tree check, then one commit for the slice (code, tests, docs, plan, state) and `state.py slice <f> done B<n> <commit>` (lands in the next slice's commit, or a final docs commit). The commit-time security hooks run on it.
   - Then straight on to the next slice (step 3; in an autopilot session, end instead).
5. **Gates.** `Slice gates: none` (default): slices run back to back without asking. They stop only at the round cap, for a backlog change that adds scope, or at a hard stop (merge, deploy, migrations, anything irreversible). The user can opt in to stops at `plan` or `commit`: `state.py set <f> "Slice gates" "plan, commit"`. (With no Prove per slice there are no per-slice findings; Feature close's findings are shown before they're fixed.)
6. **Backlog changes.** A slice that turns out too big, or work no slice covers: propose the change. A split that keeps the same FRs is made and logged (`state.py log`). Anything that adds scope (a new FR, or work outside the spec) waits for the user (`state.py blocker raise`); never add it silently.
7. **Context.** At a slice boundary, if the next slice won't fit in what's left of this session, stop with one line: `B<n> done (<commit>). Next: B<m> <title>. Run /clear, then /sdlc:start.` For a long backlog the user can run autopilot instead: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/autopilot.py" <feature>` from a terminal starts a fresh headless Claude Code session per slice, then one for Feature close, and stops on a blocked slice, a run that changed nothing, or an open trust-anchor notice. Off unless the user asks for it.
   **In an autopilot session** (the request ends with `--autopilot`): no one is there to answer. Run the one slice named (or Feature close), then end. Several active features: change nothing and end, saying why. A Feature close that can't reach Ship (the round cap, a high finding it can't fix): log why, raise it as a blocker, leave `Current:` where it stopped, and end. Never ask: `Slice gates` count as `none`, and anything that would ask (the round cap, a scope-adding backlog change, a hard stop) runs `state.py slice <f> block B<n> "<reason>"` (the row and an open question) and ends the session. Feature close ends at Ship's one-line report; end there.
8. **▶ Feature close**, once every row is `done` (in a fresh session if this one is low on context; `/sdlc:start` lands here):
   - Prove, unless `Prove: skip` (then straight to Ship): `state.py advance <f> 5` (from Stage 6) first, then one round per `prove.md`'s Feature close row, with any findings fixed back in Build (`prove.md`, Then). The ac-checker covers every acceptance criterion in the spec over the whole branch (an old plan: the verifier). The feature's one top-tier `sdlc:code-reviewer` reviews `Base..HEAD`, with diff facts `--base <Base>`, `--plan <intents>/plan.md` and one `--plan` per `plan-B*.md` (the union of their Public Surface is what's declared) and a brief on how the slices fit together. Alongside them: `sdlc:qa-tester`, `sdlc:ui-reviewer` on a UI diff, and full security when the branch is security-touched. Fixes and the one re-verification as in `prove.md` (L's `pr-test-analyzer` doesn't run here).
   - Ship (`advance <f> 8 --gate pass`): `ship.md`. Learn reads every slice's `## Fixed`. A final commit if anything changed, then Ship's one-line report (the branch is kept; merge or PR on the user's word). Then `state.py set <f> Status done`.
