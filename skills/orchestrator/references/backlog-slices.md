# Backlog slices

For a feature too big for one session, so the work can pause, `/clear` and resume between slices, or run in fresh sessions (autopilot). S never gets a backlog; a feature that fits one session keeps the plain phase loop. Each slice runs Build and Prove (`build.md`, `prove.md`'s Slice row), then commits; Ship's question and Learn wait for Feature close.

1. **Backlog.** Copy `${CLAUDE_PLUGIN_ROOT}/templates/backlog-template.md` to `<intents>/backlog.md`: one row per vertical slice (something a test or user can see working end to end), with its FRs, acceptance criteria, dependencies and size. Every spec FR is in some row. It is approved with the spec in Define's one approval, on any track. `state.py set <f> Flow lite` in the same turn as that approval message, so the user's approval also accepts the trust anchor's `Flow:` notice.
2. **Flow.** `Flow: lite` at any track and risk; tiers per the core's table. L keeps its design in Define and its Learn extras. `Base:` stays the feature's start; full security, Learn and Ship's question run once, at Feature close.
3. **Pick the slice:** `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/backlog.py" next <intents>/backlog.md` (a slice in progress, else the first `todo` whose dependencies are done; `check <backlog> B<n>` for a named one, refused while its dependencies aren't done). Nothing ready while rows remain (a `blocked:` row, or open dependencies) → say which and stop; every row `done` → Feature close. Then `state.py slice <f> start B<n>` (sets `Slice:` and `Slice base:` and the row to `in progress`) and `state.py advance <f> 4` (`--gate pass` from Define).
4. **Each slice** (phase headers as usual):
   - Build: first `<intents>/plan-B<n>.md`, short: 3–6 tasks, each naming its files, FR and test, plus a `## Public Surface` list. No planning skill. Then build as `build.md` says.
   - Prove (`advance <f> 5 --gate pass`) per `prove.md`'s Slice row: the verifier gets this slice's acceptance criteria (its backlog row), and the full suite still covers the earlier slices; the reviewer sees this slice only (diff facts with `--base <Slice base> --plan <intents>/plan-B<n>.md`, and `git diff <Slice base>`); no qa-tester (Feature close runs it once). Fixed high findings go under `## Fixed` in `<intents>/review.md`.
   - Commit: `state.py verified …` and `advance <f> 8 --gate pass`, then only the core's verified-tree check, then one commit for the slice (code, tests, docs, plan, state) and `state.py slice <f> done B<n> <commit>` (lands in the next slice's commit, or a final docs commit). The commit-time security hooks run on it.
   - Then straight on to the next slice: `state.py advance <f> 4` (in an autopilot session, end instead).
5. **Gates.** `Slice gates: none` (default): slices run back to back without asking. They stop only at the round cap, for a backlog change that adds scope, or at a hard stop (merge, deploy, migrations, anything irreversible). The user can opt in to stops at `plan`, `review` (show the findings before fixing) or `commit`: `state.py set <f> "Slice gates" "plan, commit"`.
6. **Backlog changes.** A slice that turns out too big, or work no slice covers: propose the change. A split that keeps the same FRs is made and logged (`state.py log`). Anything that adds scope (a new FR, or work outside the spec) waits for the user (`state.py blocker raise`); never add it silently.
7. **Context.** At a slice boundary, if the next slice won't fit in what's left of this session, stop with one line: `B<n> done (<commit>). Next: B<m> <title>. Run /clear, then /sdlc:start.` For a long backlog the user can run autopilot instead: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/autopilot.py" <feature>` from a terminal starts a fresh headless Claude Code session per slice, then one for Feature close, and stops on a blocked slice, a run that changed nothing, or an open trust-anchor notice. Off unless the user asks for it.
   **In an autopilot session** (the request ends with `--autopilot`): no one is there to answer. Run the one slice named (or Feature close), then end. Several active features: change nothing and end, saying why. A Feature close that can't reach Ship (the round cap, a high finding it can't fix): log why, raise it as a blocker, leave `Current:` where it stopped, and end. Never ask: `Slice gates` count as `none`, and anything that would ask (the round cap, a scope-adding backlog change, a hard stop) runs `state.py slice <f> block B<n> "<reason>"` (the row and an open question) and ends the session. Feature close ends at Ship's merge, PR or keep question; ask it and end.
8. **▶ Feature close**, once every row is `done` (in a fresh session if this one is low on context; `/sdlc:start` lands here):
   - Prove: `state.py advance <f> 5` first, then one round per `prove.md`'s Feature close row. The verifier covers the whole branch, over every acceptance criterion in the spec. The feature's one top-tier `sdlc:code-reviewer` reviews `Base..HEAD`, with diff facts `--base <Base>` and one `--plan` per `plan-B*.md` in `<intents>` (the union of their Public Surface is what's declared) and a brief on how the slices fit together. Alongside them: `sdlc:qa-tester`, `sdlc:ui-reviewer` on a UI diff, and security (light; full on L and `Risk: high`). Fixes and the one in-session re-verification as in `prove.md`, on any track (L's `pr-test-analyzer` doesn't run here).
   - Ship (`advance <f> 8 --gate pass`): `ship.md`. Learn reads every slice's `## Fixed`. A final commit if anything changed, then the merge, PR or keep question (a hard stop). Then `state.py set <f> Status done`.
