# Build (Stage 4)

- Isolation: `sdlc:using-git-worktrees` (L, or whenever the working tree is dirty).
- Always on: `sdlc:test-driven-development` (one failing test per behaviour, the code that passes it); `sdlc:systematic-debugging` the moment something fails unexpectedly.
- **Build proves its own work** (ADR 0013), where `$V` below stands for `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/verify.py"`: type that full command each time, never a shell variable or alias, or the hooks won't recognise the run (no record, and in Prove it is killed at 120 s). Build produces the evidence; Prove only judges it.
  1. Per acceptance criterion: write the test `plan.md`'s `## Acceptance tests` names, then `$V red AC-nnn` before any of its code. It records the test failing; a test that passes, can't be found or can't run is refused, so fix the test first. `manual` rows have no red step.
  2. Write the code. While coding, run only the tests near the change, not the full suite.
  3. Once, at the end: `$V`. It runs the project's verify plan (lint, typecheck, build, the full suite), each AC's test, and the drift check. Fix until it passes. A plan without `## Acceptance tests` (a feature started earlier) runs the full suite as before.
  - **Drift never stops Build.** You decide; record each in `## Deviations` in the same commit (what, why, effect: on ACs, public surface, risk, other code). `$V` fails on a changed file no task or test names, a task that changed nothing, or undeclared surface, until it has its line. The user sees every drift at the end of Prove.
- **Work from the files.** The build follows `<intents>/plan.md` (a slice: `plan-B<n>.md`), with `spec.md` and `intent.md` beside it, never from memory of the conversation. Anything that changes from the plan (a task split, another file, a different approach to a step, an AC that can't be met as written) is written under the plan's `## Deviations` with what, why and effect, and the build goes on; the user sees it at the end of Prove.
- **By `Build:`:**
  - `native`: work through the plan's tasks in this session (`Flow: full`: with `sdlc:executing-plans`, told "Prove reviews the branch" so it skips its own final review, and its `Ruling:` lines logged with `state.py log`; Lite and slices load no execution skill). Make no state updates between tasks. Lite and slices make no commits here; the full flow may commit per task, never staging `.sdlc/`.
  - `subagent`: you keep the spec, state and gates. One fresh implementer (standard tier) gets the paths to `intent.md`, `spec.md` and `plan.md` (a slice: `plan-B<n>.md`), using `sdlc:subagent-driven-development`'s `implementer-prompt.md`, plus the three steps above. It builds test first with `$V red` per AC, records deviations in the plan, runs `$V` and returns a short summary: files, tests, verify result, open issues. Tell it not to commit. Don't read the implementation. Prove's findings go back to that implementer (message it); only run the suite yourself.
  - `tasks`: `sdlc:subagent-driven-development` on `plan.md`, with one implementer and one review per task. Tell it to skip its final whole-branch review ("Prove reviews the branch"), and record the `Ruling:` lines it reports with `state.py log`, so Prove sees them.
  - `sdlc:dispatching-parallel-agents` for truly independent tasks.
- **S:** the implementer gets the state file's `Intent:` and `Repro:` lines (a feature started earlier: its `brief.md` or three files). The fix is built and verified in that one place, with no verifier or reviewer after it: a failing test reproducing the bug comes first (a new test file is allowed) and is recorded with `$V red AC-001` (the `Repro:` line is AC-001), then the fix, then `$V`; if the repro test's name or command changes, `state.py set <f> Repro …` first. Its summary quotes both results. Tell it: "stop with BLOCKED if the fix needs more than 3 files, touches auth, payments, secrets, PII or migrations, or the cause stays unclear". Don't write the fix in this session; with no subagent tool, do it here and say so. A BLOCKED for one of those reasons moves the feature to M: back to Define for a spec.
- Optional loop for a single well-specified task with a machine-checkable finish, when the optional sdlc-extras companion plugin is installed: `/sdlc-extras:ralph-loop "<task>" --completion-promise "DONE" --max-iterations 15`.
- Background: the security-guidance hooks warn on risky edits; hookify rules (if any) enforce team rules.
- **Gate:** every plan task done; `$V` passes (every AC's test recorded red and now passing, every drift recorded with what, why and effect); no TODO without a ticket. Then:
  - **No Prove** (S, M on `Flow: lite`, or `Prove: skip`): `state.py verified <f> <HEAD> <tree>` with the `tree` from `$V status`, then `state.py advance <f> 8 --gate pass` (Ship). A backlog slice instead commits as `backlog-slices.md` says.
  - **Prove** (M on `Flow: full` and L, `Prove: run`): `state.py advance <f> 5 --gate pass`.
  - **Back from Prove with findings**: fix them here, then `$V` and `state.py advance <f> 5` for the one re-verification (`prove.md`).
