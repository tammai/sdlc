# Recurring defects

One line per defect: what it looks like, then the severity.

- **A hook's command matcher misses another spelling:** a guard on file writes catches `cp`/`Set-Content` but not `mv`/`Move-Item`, a backslash or `..` path, another drive, or an abbreviated PowerShell parameter, so a protected file is written anyway; or it widens and denies ordinary commands. High (a guard that fails open). Fix with one path-normalising check on every route, not one spelling.
- **A fix for one shell breaks another:** quoting, paths or exit codes fixed for bash regress under cmd.exe or PowerShell, or the reverse. High when a hook or verify step is affected. Test each shell the fix touches.
- **Two report families share one counter or key:** a new report written into a folder or JSON that another gate counts (review rounds, waivers, grants) changes what that gate sees. High.
- **Malformed state or config crashes a script:** a lock, manifest or config value that is `null`, the wrong type or not a JSON object gives a traceback instead of `not run: <path> …`. Medium.
- **Repo config relaxes a safety stop or names a file:** a committed `.sdlc/config.json` value turns off a go-ahead (an environment marked routine skips production's stop) or becomes a path the agent reads or writes (a runbook, a reference file), checked only when a flag sets it, not when it's read back, and matched by exact name only (`prod` but not `prod-eu`). High when a stop is skipped. Fix with one check on every read: an allowlist or a plain-name pattern, the stop kept whatever the config says, paths kept inside the repo after symlinks and away from `.git/`, `.claude/` and `.sdlc/`.
- **A guard that reads command text is the only line:** each round closes the named spellings and the next finds more (subshells, `{ }`, keywords, `$( )` and backticks, comments, `\`-newline, here-docs and `<<<`, here-docs a shell reads, PowerShell's backtick escape, here-strings, `( )` and `{ }`). High when a must-never-break line rests on it. Fix: keep the text guard best effort and put a state check behind it (after each call: `git status`, local commits, push URLs) plus a structural stop where one exists (a push URL that points nowhere).
- **A value from a committed file is resolved in the wrong place:** a bare PR number looked up in the workbench instead of its repo, a repo folder that is a link to a sibling, a branch name with shell characters in a suggested command. High. Fix: resolve each against its own repo, refuse links, check names before they are recorded and quote what is suggested.
- **A containment check crashes across drives:** `os.path.commonpath` (or `relpath`) raises `ValueError` when a link or path resolves to another Windows drive, so a "stays inside the repo" check ends in a generic error instead of its refusal. High when the refusal is the spec's contract. Fix: treat the `ValueError` as outside.
- **A path rule checked on one form of the path only:** a file named by repo config (or reached through a default path) is checked as written but not where its links lead, or one rule (the extension, a barred folder, control characters) runs on one form and another rule on the other, so a committed link reaches `.env`, `.git` or `.claude` and its text is printed to the agent. High. Fix: one function holding every rule, run on the written path and the resolved one (`scripts/objects.py` `_refused`), with a link test per rule.
- **A reviewer told to run what its read-only rule forbids:** a review instruction (review-brief.md, an agent prompt) says to run a plugin script to learn something, while `sdlc:code-reviewer` may run only the project's test command, so the check is skipped or the rule is broken. High when the skipped check is a spec requirement. Fix: the orchestrator works it out and names it in the review's prompt.
- **A configurable safety cap the agent can raise by some route:** a limit read from a file the agent can edit (a round cap, a budget) is bounded by min/max of "now", "at Base" and "what the user set", and each review finds another order of writes that climbs back (a raise applied on any reply, a lower value it never saw, a restore before the next check). High. Fix with a ratchet: a stored ceiling that follows the file down on every call and goes up only on the user's own act, read from their prompt, not from a file write.
- **A changed rule is still restated in the old words:** CHANGELOG, wiki, agent prompt or flow.md still describes the old behaviour. Medium (fix in passing when wording only).
