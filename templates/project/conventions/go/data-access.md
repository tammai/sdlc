# Go API (sqlc, pgx): data access

- Queries are SQL in `db/queries/`, one file per domain, compiled to typed Go by sqlc. Only `internal/store`
  talks to the database.
- Every query takes what scopes its rows as a named parameter (`@tenant_id` in a multi-tenant product); dynamic
  filters are optional named parameters in SQL, never query text built in Go.
- Generated code is committed and regenerated by `go generate ./...`.
- One `pgxpool.Pool`, created at startup with an explicit `MaxConns` and `MaxConnIdleTime`.
- Transactions: the service begins a `pgx.Tx`, passes `queries.WithTx(tx)` to the store calls, and commits or
  rolls back in one place.
- Migration files are numbered with zero padding (sqlc reads them in lexical order).
- Tests run the store against a real database, not mocks.
