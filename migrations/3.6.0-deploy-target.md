summary: setup records how the project deploys (target, environments, runbook), which /sdlc:deploy and Define read; the migrations rule also covers drizzle/, alembic/ and db/migration/
---

sdlc 3.6 asks how a project deploys and records it as `deploy` in `.sdlc/config.json`: the target, the environments (each routine or not) and the deploy runbook. `/sdlc:deploy` follows the runbook and lets only a routine environment deploy without a go-ahead; Define sees the platform's checks (`brief.py` prints them) when sdlc has a reference for the target.

1. **Record the deploy target.** Run setup's `deploy` step (`skills/setting-up-projects/SKILL.md`, Common steps): ask the target and the environments (a hard stop), then `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/scaffold.py" deploy --target <t> --env <name>[:routine] …`. A deploy runbook the repo already has (`knowledge/runbooks/*deploy*.md`, say): pass it as `--runbook <path>` and don't seed another; offer to add any of the template's sections it lacks (Environments, Deploy, Smoke test, Rollback, Logs, Learnt on deploys) as a diff the user approves. Seed or edit a runbook only at the `runbook` path the command printed; when it's null or listed under `invalid`, say so and write nothing. The user doesn't know yet → `--target none`; `/sdlc:setup deploy` records it later.
2. **Migration globs.** The default `areas.migrations` now also matches `**/drizzle/**`, `**/alembic/**` and `**/db/migration/**`; the regenerate step re-renders `.claude/rules/sdlc-migrations.md` with them. A repo that sets its own `areas.migrations` keeps its list: if its migrations live in one of those folders and the list misses them, propose adding the folder.
3. **Commit** with the upgrade (`chore(sdlc): upgrade to 3.6`).
