summary: Give the project a product doc (PRD), or record the one it already has
---

From 2.0 every set-up project has a product doc: the problem, who it's for, goals and non-goals, the core capabilities, constraints and success measures. Define reads it as background when a change touches product scope. It's user-owned: sdlc never overwrites it, and eject keeps it.

1. `$S prd` says where it's expected and whether it exists. If it exists, this migration is done: apply it.
2. Otherwise run setup's `prd` step (`SKILL.md`, Common steps): use a PRD the repo already has as is (`$S prd <path>`), or draft one from the README, docs, routes, models and screens with every guessed line marked "(inferred, confirm)". It's a hard stop: show the draft and write it to `<docs>/prd.md` only after the user approves, then `$S prd <docs>/prd.md`.
3. The user doesn't want one now: skip this migration with that reason. `/sdlc:doctor` keeps warning until there is one.
4. Commit `docs(sdlc): product doc`.
