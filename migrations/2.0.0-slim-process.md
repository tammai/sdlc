sdlc 2.0 keeps the record and the guards and drops Prove's rounds and extra agents. Every change, S to L, gets `intent.md`, `spec.md` (each criterion with its test) and `plan.md`, and `review.md` after the build. The agent asks only when what, why or how isn't clear. After the build, the agent recommends which reviews to run. Lessons are distilled before the merge. The agent stops at the PR. A feature's state now carries `Process: 2`, and the phases are Define, Build, Review and Ship (stages 1, 4, 5, 8).

1. **Old features first.** If `$S upgrade-plan` → `old_features` is not empty, stop. Name each feature and tell the user to finish it with sdlc 1.8.1 (`/plugin install sdlc@sdlc` at 1.8.1), or to archive it by setting its `Status:` to `done`, before upgrading. `$S set-version` refuses until none is left.
2. **Rules.** Regenerate every entry in `$S upgrade-plan` → `regenerate`; the policy rules now name the 2.0 phases.
3. **Removed agents.** If the repo copied the plugin's `verifier`, `ac-checker` or `code-architect` agent into `.claude/agents/`, offer to delete the copy; it no longer exists in the plugin.
4. **Commit** `chore(sdlc): upgrade to 2.0`. Point the user at the 2.0.0 section of the plugin's CHANGELOG.
