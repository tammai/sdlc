sdlc 3.5 adds nothing to a standalone repo. A spec-backed repo, one with its own rspec `criteria.lock.json` (or `spec_lock` in `.sdlc/config.json`) or `acceptance/manifest.json`, also has `accept.start` and `accept.base_url`: how the recorded acceptance tests start the build and reach it. `/sdlc:doctor` warns while they are empty, in a spec-backed repo only.

1. Run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/scaffold.py" add-config-keys`. In a spec-backed repo it adds each key still missing with an empty value (`""`) and keeps every value already set; elsewhere it adds nothing and says so. It prints the keys it added, and is safe to run twice.
2. If it added keys, offer to fill them now, as setup does (`setting-up-projects/references/brownfield.md`, Acceptance keys): the start command and the base URL. The user may leave them empty for later.
3. **Commit** `.sdlc/config.json` with the upgrade, when it changed.
